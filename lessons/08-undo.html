undo-effects, 봇이 지운 파일을 한 줄로 되살리는 안전장치

지우기 직전에 사본을 떠 두는 커뮤니티 플러그인으로 롤백 연습하기

S 바로 활용6차시 PART 4 서버 지키기 (롤백 시연)25분중급
원본 사례: @witcheer · 2026-11-07

한 줄 요약

봇이 파일을 지우거나 덮어쓰기 직전에 사본을 저장해 두고, /undo-effects restore 한 줄로 되돌리는 헤르메스 플러그인입니다.

원본 사례

헤르메스 커뮤니티 소식을 정리해 올리는 @witcheer가 2026년 11월 7일(미국 시각) 30초짜리 시연 영상과 함께 이 플러그인을 소개했습니다.

"헤르메스 에이전트가 파일을 지우거나 덮어썼다면, 명령 하나로 되돌릴 수 있다." (@witcheer, 번역)

만든 사람은 GitHub 사용자 Moodtuner997이고, MIT 라이선스 오픈소스입니다. 11월 4일에 저장소가 만들어졌고, 공식 헤르메스 플러그인 카탈로그에 커뮤니티 등급(community)으로 등록됐습니다. 버전은 0.1.2이고 헤르메스 0.22.7 이상이 필요합니다.

작동 방식은 단순합니다.

  1. 봇이 rm(삭제), mv(이동), sed -i(파일 안 글자 바꾸기), >(덮어쓰기) 같은 명령이나 파일 쓰기 도구를 실행하려고 하면,
  2. 실행 직전에 영향을 받을 파일을 몰래 복사해 둡니다.
  3. 명령은 원래대로 실행됩니다. 막거나 바꾸지 않습니다.
  4. 나중에 /undo-effects list 로 무슨 일이 있었는지 보고, /undo-effects restore 1 로 되돌립니다.

저장소 설명서에 나오는 예시 화면을 번역하면 이렇습니다.

text
> /undo-effects list
최근 효과 3개, 최신 순
  1  14:07:12  terminal    rm -rf build/ dist/      파일 2개, 1.2MB 저장
  2  14:05:40  write_file  src/config.py            파일 1개, 2.1KB 저장
  3  14:02:03  terminal    git clean -fd            지원 안 됨(not covered)

> /undo-effects restore 1
경로 2개 복원 완료. 교체된 내용도 보관했으니 다시 되돌릴 수 있음.

설명서가 강조하는 안전 규칙이 세 가지 있습니다.

  • 봇이 바꾼 뒤에 내가 직접 고친 파일은 덮어쓰지 않습니다. (강제로 하려면 --force)
  • 복원하면서 바뀌는 내용도 사본을 남겨서 복원 자체도 되돌릴 수 있습니다.
  • 분석하지 못한 명령은 조용히 넘어가지 않고 "not covered(지원 안 됨)"라고 솔직하게 표시합니다.

왜 헤르메스반에 중요한가

  • 6차시 PART 4 롤백 시연과 짝입니다. 깃허브 백업은 "프로젝트 전체를 예전 상태로", undo-effects 는 "방금 봇이 지운 파일 하나를 되살리기"입니다. 두 가지를 같이 알면 겁이 줄어듭니다.
  • 우리 봇은 서버에서 혼자 일합니다. 밤 11시 크론잡이 블로그 기록 파일이나 디자인.md 를 잘못 덮어써도 우리는 자는 중입니다.
  • 5차시 6번 규칙(이미 쓴 글은 다시 쓰지 않는다)은 기록 파일에 의존합니다. 그 기록 파일이 지워지면 같은 글이 또 올라갈 수 있습니다. 되살릴 방법이 있어야 합니다.
  • 설치가 한 줄입니다. 텔레그램으로 봇에게 시키면 됩니다. 4차시에 버퍼 MCP 를 봇에게 설치시킨 것과 같은 방식입니다.

구조 한눈에 보기

  1. 1봇의 작업크론잡이나 내 지시로 파일을 지우거나 덮어씀
  2. 2직전 사본undo-effects 가 대상 파일을 먼저 복사
  3. 3그대로 실행명령은 막지 않고 원래대로 실행
  4. 4사고 발견"어? 기록 파일이 사라졌네"
  5. 5목록 확인/undo-effects list 로 언제 무엇이 바뀌었는지 보기
  6. 6복원/undo-effects restore 번호 로 되살리기

헤르메스에는 비슷한 내장 기능인 체크포인트와 /rollback 도 있습니다. 다만 공식 문서에 따르면 체크포인트는 기본으로 꺼져 있어서 따로 켜야 합니다. undo-effects 는 플러그인을 켜기만 하면 git 저장소가 아닌 일반 폴더에서도 동작한다는 점이 다릅니다.

핵심 개념

  • 플러그인(plugin): 스마트폰 앱처럼 헤르메스에 기능을 추가로 설치하는 것. 설치 후 "켜기(enable)"까지 해야 작동합니다.
  • 스냅숏(snapshot): 지우기 직전에 찍어 두는 사진. 사진이 있으니 원래대로 돌릴 수 있습니다.
  • 효과(effect): 봇의 명령 때문에 실제로 바뀐 파일. undo-effects 는 이 목록을 시간순으로 보여 줍니다.
  • 복원(restore): 사진을 보고 원래 자리에 다시 놓는 것. 미리보기(--dry-run)로 먼저 확인할 수 있습니다.
  • not covered: "이건 제가 사진을 못 찍었어요"라는 정직한 표시. 이 표시가 붙은 것은 되살릴 수 없습니다.

실습: 따라 하기

실습은 반드시 연습용 폴더에서만 합니다. 크론잡이 쓰는 진짜 파일로 연습하지 않습니다.

1단계: 헤르메스 버전 확인

텔레그램 · 내 봇에게
서버에서 hermes --version 을 실행해서 버전만 알려 줘. 아무것도 바꾸지 마.

0.22.7 보다 낮으면 오늘은 시연만 보고, 업데이트는 개별 지원 시간에 합니다.

2단계: 플러그인 설치 (미리보기 후 통과)

텔레그램 · 내 봇에게
헤르메스 공식 카탈로그에서 undo-effects 플러그인을 설치하고 켜 줘.
명령은 hermes plugins install undo-effects --enable 이야.
실행하기 전에 명령과 설치될 플러그인 정보를 먼저 보여 주고 내 "통과"를 받아.
설치가 끝나면 hermes plugins list 로 enabled 상태인지 보여 줘.

설치 중에 권한을 묻는 화면이 나오면 내용을 읽고 허용합니다. 설치가 끝나면 새 기능을 확실히 불러오도록 게이트웨이를 다시 켭니다.

텔레그램 · 내 봇에게
게이트웨이를 재시작해 줘. 재시작 후 내가 다시 말을 걸면 /undo-effects doctor 결과를 보여 줘.

봇이 스스로 재시작을 못 하면 서버 까만 창에서 직접 실행합니다.

서버 터미널
hermes gateway restart

3단계: 연습용 파일 만들기

텔레그램 · 내 봇에게
홈 폴더에 undo-practice 라는 연습 폴더를 만들고,
그 안에 memo.txt 파일을 만들어서 "오늘의 다짐: 봇은 실수할 수 있다" 한 줄을 써 줘.
다 되면 파일 내용을 보여 줘.

4단계: 일부러 사고 내기

텔레그램 · 내 봇에게
undo-practice/memo.txt 파일을 rm 명령으로 삭제해 줘. 연습이니까 삭제해도 괜찮아.
삭제한 뒤 폴더 안 파일 목록을 보여 줘.

파일이 사라진 것을 확인합니다. 승인 요청이 뜨면 연습이므로 허용합니다.

5단계: 목록 보고 되살리기

텔레그램에 아래 명령을 그대로 보냅니다.

텔레그램 · 내 봇에게
/undo-effects list

방금 삭제한 기록의 번호를 확인한 뒤, 먼저 미리보기를 합니다.

텔레그램 · 내 봇에게
/undo-effects restore 1 --dry-run

문제가 없으면 실제로 복원합니다.

텔레그램 · 내 봇에게
/undo-effects restore 1

마지막으로 확인합니다.

텔레그램 · 내 봇에게
undo-practice/memo.txt 내용을 보여 줘.

"오늘의 다짐" 한 줄이 다시 보이면 성공입니다. 텔레그램에서 슬래시 명령이 안 먹으면, 같은 기능을 서버 명령으로 실행하라고 봇에게 시킵니다.

텔레그램 · 내 봇에게
서버에서 hermes undo-effects list 를 실행해서 결과를 보여 줘.

6단계: 정리

텔레그램 · 내 봇에게
undo-practice 폴더 안 내용을 보여 주고, 내가 "통과"라고 하면 폴더를 삭제해 줘.

응용 아이디어

  • 1인 크리에이터: 크론잡 규칙에 "기록 파일이나 디자인.md 를 바꾸기 전에는 바꿀 내용을 텔레그램으로 먼저 보여 줘"를 추가하고, undo-effects 를 마지막 안전망으로 둡니다.
  • 소상공인: 봇이 관리하는 가격표, 재고 메모 파일이 있다면 "매주 /undo-effects list 를 보고 이상한 삭제가 없었는지 알려 줘" 크론잡을 만듭니다.
  • 강사: 수강생 과제 파일을 봇이 정리하게 할 때, 정리 전후로 list 를 캡처해 두면 실수 추적이 쉽습니다.
  • 직장인: 보고서 초안을 봇이 계속 고쳐 쓰는 작업이라면, 마음에 들던 이전 버전으로 restore 해서 비교합니다.
  • 튠업과 묶기: 일요일 튠업 프롬프트에 "/undo-effects doctor 결과"를 한 줄 추가합니다.

수강생 미션

기본 미션

  • 2~5단계를 따라 연습 파일을 지우고 되살립니다.
  • 제출물: /undo-effects list 화면과 복원 후 memo.txt 내용 화면 캡처 각 1장.

도전 미션

  • 연습 파일을 지우는 대신 sed -i 로 글자를 바꾸게 한 뒤 되돌려 봅니다.
  • git clean 같은 "not covered" 명령이 목록에 어떻게 표시되는지 연습 폴더에서 확인합니다. (연습 폴더 밖에서는 절대 하지 않기)
  • 제출물: not covered 표시 화면 캡처 + "왜 이것은 되살릴 수 없는지" 한 줄 설명.

체크리스트

  • 헤르메스 버전이 0.22.7 이상인지 확인했다
  • 설치 명령을 미리보기로 보고 통과했다
  • hermes plugins list 에서 undo-effects 가 enabled 로 보인다
  • 연습 폴더에서만 삭제 실습을 했다
  • restore 전에 --dry-run 으로 미리보기를 했다
  • 복원 후 파일 내용이 원래대로인 것을 확인했다
  • 이 플러그인이 되돌리지 못하는 것(버퍼 예약, 보낸 메시지 등)을 이해했다

주의할 점과 한계

  • 파일만 되돌립니다. 버퍼에 걸린 예약, 텔레그램으로 보낸 메시지, MCP 로 한 작업은 되돌리지 못합니다(설명서에 v1 범위 밖이라고 명시). 발행 사고는 5차시 승인 규칙으로 막아야 합니다.
  • 지원 안 되는 명령이 있습니다. git clean, git reset --hard, xargs rm, find -exec, 파이썬 코드로 직접 쓰는 경우 등은 "not covered"로 표시만 되고 사본이 없습니다.
  • .env 같은 비밀 파일은 일부러 저장하지 않습니다. 키가 든 파일이 지워지면 이 플러그인으로는 못 살립니다. API 키는 구글 시트 등 따로 보관하라는 4차시 원칙을 지킵니다.
  • 사본은 암호화되지 않습니다. 서버의 HERMES_HOME/plugin-data/undo-effects/ 폴더에 그대로 저장되고 기본 14일 보관됩니다. 평범한 이름의 파일에 비밀을 적어 두면 그것도 복사됩니다.
  • 봇이 저장소 폴더 자체를 지우면 막을 수 없습니다. 설명서가 직접 밝힌 한계입니다. 깃허브 백업과 함께 쓰는 이중 안전망으로 생각합니다.
  • 원격 실행 환경에서는 작동하지 않습니다. 터미널이 원격 샌드박스로 설정돼 있으면 동작하지 않고 doctor 가 경고합니다. 우리처럼 서버에서 직접 도는 기본 설정은 해당됩니다.
  • 커뮤니티 플러그인입니다. 공식 카탈로그 심사는 거쳤지만 Nous Research 가 만든 것은 아닙니다. 설명서에는 헤르메스 0.22.7 에서만 시험했다고 적혀 있습니다.
  • 텔레그램에서 /undo-effects 슬래시 명령이 동작하는지는 직접 시험하지 못했습니다. 공식 문서상 플러그인 슬래시 명령은 게이트웨이 세션에도 등록되지만, 안 되면 5단계의 서버 명령 방식으로 대신합니다.
  • 원문의 설치 명령(hermes plugins install undo-effects --enable)은 공식 문서의 --enable 옵션 설명과 일치합니다. 저장소 설명서는 install 과 enable 을 두 줄로 나눠 적었는데 결과는 같습니다.

강사 노트

시간 내용
0~3분 "깃허브 백업은 전체 되감기, undo-effects 는 방금 지운 것 되살리기" 비교
3~8분 1~2단계 버전 확인과 설치 (강사 봇으로 먼저 시연)
8~18분 3~5단계 삭제와 복원 실습 동시 진행
18~22분 not covered 와 되돌릴 수 없는 것(버퍼 예약) 설명
22~25분 정리, 과제 안내

시연 팁:

  • 강사 서버에는 수업 전에 미리 설치하고 게이트웨이 재시작까지 끝내 둡니다. 현장 설치는 시간이 밀릴 수 있습니다.
  • 삭제 장면에서 "앗, 지워졌다" 하고 잠깐 멈추면 복원의 감동이 커집니다.
  • list 화면의 not covered 줄을 일부러 하나 만들어 두면 한계를 설명하기 좋습니다.

예상 질문:

  • Q. 크론잡이 잘못 올린 쓰레드 글도 되돌릴 수 있나요? A. 아니요. 이 플러그인은 서버 안의 파일만 되살립니다. 발행은 미리보기와 "통과" 규칙으로 막습니다.
  • Q. 보관된 사본 때문에 서버 용량이 차지 않나요? A. 기본 14일이 지나면 정리되고, 파일 하나 50MB, 한 번에 200MB 까지만 저장합니다. /undo-effects prune 으로 직접 정리할 수도 있습니다.
  • Q. 체크포인트(/rollback)와 뭐가 달라요? A. 체크포인트는 헤르메스 내장 기능이지만 기본으로 꺼져 있고 git 방식으로 저장합니다. undo-effects 는 켜기만 하면 일반 폴더에서도 파일 단위로 되살립니다. 둘을 같이 써도 됩니다.
