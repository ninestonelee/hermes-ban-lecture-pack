## 한 줄 요약

서버는 집(클라우드)에 두고, 휴대폰으로는 지시하고 승인만 합니다. 헤르메스에는 위험한 명령 전에 사람에게 묻는 승인 기능이 기본으로 켜져 있습니다.

## 원본 사례

2026년 11월 1일, 헤르메스 팁을 꾸준히 올리는 @BkashJosi가 "휴대폰에서 헤르메스를 쓰는 5가지 방법"을 정리했습니다.

> "노트북은 집에 있고, 헤르메스는 계속 일하고, 휴대폰이 그것을 조종한다." (@BkashJosi)

1. **손이 바쁠 때, 음성 메모**: 텔레그램 음성 메모가 글로 바뀌어 일반 메시지처럼 실행됩니다. 로컬 음성 인식은 키가 필요 없습니다.
2. **명령이 미심쩍을 때, 휴대폰으로 승인**: 텔레그램에 허용·거부 버튼이 오고, 아무 연결된 채팅에서 `/approve` 또는 `/deny`로 답할 수도 있습니다. 승인 기능은 기본으로 켜져 있습니다.
3. **긴 작업일 때, /bg**: `/bg 작업내용`을 보내고 휴대폰을 주머니에 넣으면 결과가 채팅으로 돌아옵니다.
4. **채팅 앱이 없을 때, ntfy**: 무료 ntfy 앱으로 답을 푸시 알림으로 받습니다.
5. **크론잡 결과를 휴대폰으로, /sethome**: 결과를 받을 채팅에서 `/sethome`을 보냅니다.

덧붙여, 텔레그램에서는 기본 설정상 **최종 답과 승인 요청만 알림이 울리고** 진행 중 메시지는 조용히 옵니다. 같은 날 공식 모바일 앱이 아이폰·안드로이드 오픈 베타로 나왔다고 알렸습니다.

## 왜 헤르메스반에 중요한가

5차시에 우리는 밤 11시 크론잡에 "텔레그램 미리보기 → 통과면 버퍼 예약, 취소면 발행 안 함, 수정이면 고쳐서 다시, 아침 8시까지 답 없으면 발행 안 함" 규칙을 붙였습니다. 이 사례는 그 생각이 헤르메스 안에 **공식 기능**으로도 들어 있다는 것을 보여 줍니다.

- 우리가 만든 통과 규칙은 **콘텐츠 승인**입니다. 프롬프트로 직접 정한 규칙입니다.
- 헤르메스 기본 승인은 **명령 승인**입니다. 파일 삭제처럼 위험한 서버 명령 앞에서 자동으로 멈춥니다.
- 둘 다 "답이 없으면 하지 않는다"가 기본입니다. 우리 5번 규칙(8시까지 답 없으면 발행 안 함)과 공식 승인 타임아웃(기본 300초, 응답 없으면 거부)이 같은 원리입니다.
- `/sethome`은 3차시에 크론 결과를 받을 때 이미 쓴 바로 그 기능입니다.

## 구조 한눈에 보기

```flow
휴대폰 | 글이나 음성 메모로 지시
텔레그램 봇 | 서버의 헤르메스에 전달
헤르메스 판단 | 안전하면 진행, 위험하면 멈춤
승인 요청 | 휴대폰에 알림과 버튼 도착
사람의 답 | 승인하면 실행, 거부나 무응답이면 중단
결과 | 같은 채팅 또는 홈 채널로 배달
```

## 핵심 개념

- **명령 승인(Exec Approval)**: 공사장의 안전 관리자. 위험한 작업 앞에서 "진행할까요?"라고 꼭 묻습니다.
- **승인 모드 smart(기본)**: 똑똑한 경비원. 안전한 건 통과, 확실히 위험한 건 차단, 애매하면 사람에게 물어봅니다.
- **타임아웃**: 대답 없으면 문을 닫는 자동문. 기본 300초 동안 답이 없으면 실행하지 않습니다.
- **/bg 백그라운드 작업**: 심부름꾼을 따로 보내기. 지금 대화와 별개로 일하고 끝나면 보고합니다. 단, 지금 대화 내용은 모릅니다.
- **홈 채널(/sethome)**: 크론잡 결과를 받는 우편함.

## 실습: 따라 하기

### 1단계: 우편함과 알림 확인

```prompt
/sethome
```

```prompt
지금 이 채팅이 크론잡 결과를 받는 홈 채널이 맞는지, 그리고 텔레그램 알림 설정이 어떻게 돼 있는지 설명해 줘. 설정은 바꾸지 마.
```

### 2단계: 음성 메모로 지시하기

텔레그램 마이크 버튼을 누르고 이렇게 말해 봅니다.

> "오늘 밤 크론잡이 쓸 블로그 글이 뭔지 제목만 알려 줘."

글로 바뀌어 처리되면 성공입니다. 음성이 글로 바뀌지 않으면 아래를 보냅니다.

```prompt
내가 보낸 음성 메모가 글로 바뀌지 않았어. 음성 인식(STT) 설정 상태를 확인하고, 키가 필요 없는 로컬 방식으로 켜려면 무엇이 필요한지 알려 줘. 설치는 내가 승인한 뒤에 해.
```

### 3단계: 승인 기능 확인하기 (안전한 연습용 파일로)

먼저 지워도 되는 연습용 폴더를 만듭니다.

```prompt
서버 홈 폴더에 "승인연습"이라는 폴더를 만들고 그 안에 빈 파일 3개를 만들어 줘. 만든 경로를 알려 줘.
```

그다음 일부러 삭제를 요청합니다.

```prompt
방금 만든 "승인연습" 폴더를 통째로 삭제해 줘.
```

승인 요청이 오면 **처음엔 거부**해 봅니다(거부 버튼 또는 `/deny`). 폴더가 그대로인지 확인한 뒤, 다시 요청해서 이번엔 승인(`/approve`)해 봅니다. 봇이 승인 없이 바로 지웠다면 4단계 설정 확인으로 넘어갑니다.

### 4단계: 승인 설정 점검

```prompt
지금 위험 명령 승인 설정(approvals.mode, timeout, cron_mode)이 각각 무엇으로 돼 있는지 표로 보여 줘. 각 값이 무슨 뜻인지 쉬운 말로 한 줄씩. 아무것도 바꾸지 마.
```

공식 기본값은 mode: smart, timeout: 300초, cron_mode: deny입니다. off나 yolo로 돼 있다면 강사와 상의하세요.

### 5단계: /bg로 긴 작업 맡기기

```prompt
/bg 지난 일주일 동안 밤 11시 크론잡이 만든 글의 제목과 통과·취소·수정 결과를 표로 정리해 줘. 아무것도 발행하거나 예약하지 마.
```

다른 질문을 하면서 기다리다가, "Background task complete" 메시지로 결과가 오는지 확인합니다.

## 응용 아이디어

- **소상공인**: 매장에서 손이 바쁠 때 음성 메모로 "오늘 품절 메뉴 공지 초안 써 줘", 미리보기 후 통과.
- **1인 크리에이터**: 촬영 이동 중 `/bg 이번 주 쇼츠 아이디어 10개 조사해서 표로`.
- **강사**: 수업 직전 음성으로 "오늘 과제 제출 안 한 사람 명단 정리"(파일 정리만, 문자 발송 금지).
- **직장인**: 회의 중 `/bg 어제 메모를 주간 보고 초안으로`, 회의 끝나면 확인.
- **가족 단체방**: 봇을 단체방에 넣을 때는 승인할 수 있는 사람을 나로 제한(approvals.approvers)하는 설정을 강사와 함께 검토.

## 수강생 미션

### 기본 미션

3단계 승인 연습을 끝까지 해 봅니다. 제출물: 승인 요청 메시지 캡처 1장, 거부 후 폴더가 남아 있다는 봇의 답 캡처 1장.

### 도전 미션

음성 메모로 밤 11시 크론잡 미리보기에 "수정: 제목을 질문형으로"라고 답해 봅니다. 제출물: 음성 메모와 수정된 미리보기 캡처, 그리고 4단계 승인 설정 표 캡처.

## 체크리스트

- [ ] /sethome 으로 홈 채널을 정했다
- [ ] 음성 메모가 글로 바뀌어 실행되는 것을 확인했다
- [ ] 연습용 폴더로 거부와 승인을 각각 한 번씩 해 봤다
- [ ] 내 승인 설정(mode, timeout, cron_mode)을 알고 있다
- [ ] /bg 결과가 채팅으로 돌아오는 것을 확인했다
- [ ] 크론잡의 통과 규칙(콘텐츠 승인)과 명령 승인의 차이를 설명할 수 있다

## 주의할 점과 한계

- **크론잡은 명령 승인을 물어보지 않습니다.** 공식 문서상 크론 실행 중 위험 명령은 기본값(cron_mode: deny)으로 그냥 차단됩니다. 밤사이 사람에게 묻는 구조가 아니므로, 콘텐츠 발행 같은 확인은 5차시처럼 프롬프트 규칙으로 넣어야 합니다.
- **YOLO와 off는 쓰지 마세요.** 승인 모드를 off로 하거나 /yolo를 켜면 모든 안전 질문이 사라집니다. 공식 문서도 신뢰된 환경에서만 쓰라고 경고합니다.
- **승인 전 명령을 끝까지 읽으세요.** 공식 문서상 명령이 너무 길어 다 못 보여 주면 거부만 할 수 있게 됩니다. 이해 못 하는 명령은 거부가 정답입니다.
- **/bg는 지금 대화를 모릅니다.** 필요한 정보는 /bg 문장 안에 모두 적어야 합니다.
- **버튼 문구는 다를 수 있습니다.** 원문의 "Allow Once / Deny" 버튼 이름은 공식 문서에서 정확히 확인하지 못했습니다. 문서에는 yes, approve, ok 등으로 승인하고 no, deny, cancel 등으로 거부한다고 적혀 있습니다.
- **모바일 앱 상태**: 원문은 11/1에 "오픈 베타"라고 했지만, 11/25 현재 공식 모바일 페이지는 베타 대기자 등록(waitlist) 화면입니다. 설치 가능 여부는 직접 확인하세요. 수업에서는 텔레그램만으로 충분합니다.
- **ntfy**는 공식 지원 목록에 있으나 이번 교재에서 설정은 다루지 않았습니다.

## 강사 노트

| 구간 | 시간 | 내용 |
| --- | --- | --- |
| 사례 소개 | 4분 | 5가지 방법, "휴대폰은 리모컨" |
| 개념 정리 | 5분 | 콘텐츠 승인(통과 규칙) vs 명령 승인 |
| 시연 | 8분 | 연습 폴더 삭제 → 거부 → 승인 |
| 실습 | 6분 | 각자 2단계, 3단계 |
| 정리 | 2분 | 체크리스트, 미션 |

시연 팁: 실제 파일로 삭제 시연은 절대 하지 말고 반드시 "승인연습" 폴더로만 하세요. smart 모드에서는 빈 폴더 삭제를 위험하지 않다고 보고 바로 실행할 수도 있습니다. 그 경우 "smart는 이렇게 스스로 판단한다"는 설명 기회로 쓰고, 승인 요청이 뜨는 화면은 미리 캡처해 둔 것을 보여 주세요.

예상 질문과 답

- Q. 자는 동안 승인 요청이 오면요? A. 기본 300초 안에 답이 없으면 실행하지 않습니다. 크론잡은 애초에 묻지 않고 막습니다. 안전 쪽으로 기본값이 잡혀 있습니다.
- Q. 매번 승인하기 귀찮아요. A. 귀찮음이 곧 안전장치입니다. 자주 쓰는 안전한 작업은 스킬이나 크론잡으로 만들어 승인 횟수 자체를 줄이세요.
- Q. 가족이나 직원도 봇을 쓰게 하고 싶어요. A. 단체방에서는 누가 승인할 수 있는지(approvals.approvers) 먼저 정해야 합니다. 개별 지원 시간에 같이 설정합니다.
