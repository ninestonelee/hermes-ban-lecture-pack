## 한 줄 요약

헤르메스에 "직원"을 한 명씩 채용한다. 직원마다 별도 프로필(책상)을 주고, 한 가지 일만 맡기고, 일시정지 상태의 크론잡(근무표)으로 시작해 확인한 뒤 켠다.

## 원본 사례

헤르메스 팁을 꾸준히 올리는 @BkashJosi(Hermes Super-Intel)는 2026년 11월 3일 "이번 주에 직원 2명부터 뽑아 보라"는 글을 올렸다.

- **리서치 직원**: 매주 월요일, 내 주제의 새 arXiv 논문을 찾아 링크가 달린 5줄로 보내 준다. 스킬은 arxiv, grounded-citations.
- **코딩 직원**: 평일 오전 9시, 열려 있는 풀 리퀘스트와 실패한 검사를 보고 무엇부터 고칠지 초안으로 정리한다. 스킬은 github.

> 직원마다 자기 프로필, SOUL.md, 메모리, 그리고 일시정지된 근무표를 갖는다. 두 직원 모두 같은 8단계다. (@BkashJosi, 번역)

본인 답글에는 리서치 직원을 만드는 명령 두 줄을 공개했다.

```bash
hermes profile create researcher --description "Weekly sourced paper digest"
hermes -p researcher cron create "0 9 * * 1" "Find this week's new arXiv papers on <your topic>. 5 bullets, each with its link. Draft only." --skill arxiv --skill grounded-citations
```

함께 링크한 X 아티클 "8 steps to hire Hermes Agent employee"에서는 직원 하나가 여섯 가지로 이뤄진다고 설명한다.

| 직원의 구성 | 헤르메스 기능 |
|---|---|
| 책상 | 프로필 |
| 직무기술서 | SOUL.md |
| 교육 | 스킬 |
| 업무 수첩 | 메모리 (MEMORY.md, USER.md) |
| 근무표 | 크론잡 |
| 관리자 결재 | 승인(approvals) 설정 |

아티클의 핵심 조언은 세 가지다. 직무를 한 문장으로 쓰고, 직원마다 책상(프로필)을 따로 주고, 새 직원은 수동 결재(manual)로 시작하라는 것이다. "그리고 또"가 필요하면 그건 두 번째 직원이라고 한다.

## 왜 헤르메스반에 중요한가

우리는 3차시에 밤 11시 크론잡을 걸었고, 5차시에 "미리보기 → 통과 → 버퍼 예약" 규칙을 붙였다. 지금은 봇 하나가 모든 일을 한다.

- **다음 크론잡을 어디에 둘까**: 크론잡이 늘어나면 한 봇의 메모리와 규칙이 섞인다. 블로그 담당 규칙이 뉴스 요약에 새어 나가는 식이다. 직원(프로필)을 나누면 섞이지 않는다.
- **일시정지 상태로 시작**: 5차시의 "답 없으면 발행 안 함" 규칙과 같은 정신이다. 처음부터 켜지 않고, 한 번 읽어 보고 켠다.
- **초안만**: 원문 직원도 "Draft only(초안만)"가 기본이다. 우리 수업의 승인 습관과 같다.
- **졸업 후 혼자 확장하는 틀**: 8단계를 한 번 익히면 아침 브리핑, 메일 정리 같은 직원을 같은 방법으로 계속 뽑을 수 있다.

## 구조 한눈에 보기

```flow
직무 한 문장 | 매주 월요일, 내 분야 뉴스 5줄을 링크와 함께 초안으로
책상(프로필) | hermes profile create 로 별도 공간 만들기
직무기술서(SOUL.md) | 한 가지 일과 하지 말아야 할 일 적기
교육(스킬) | 필요한 스킬만 붙이기
근무표(크론) | 일시정지로 만들고, 읽어 보고, 켜기
결재와 평가 | 결과를 일주일 보고 계속 둘지 결정
```

## 핵심 개념

- **프로필**: 직원의 책상. 설정, 메모리, 스킬, 크론잡이 따로 보관된다. 프로필 이름이 곧 명령어가 된다 (예: `researcher chat`).
- **SOUL.md**: 직원의 직무기술서. 시스템 프롬프트 맨 앞에 들어가 "나는 누구이고 무엇을 하는가"를 정한다.
- **스킬**: 직원 교육 매뉴얼. 필요한 것만 붙여야 딴짓을 덜 한다.
- **크론 표현식**: 근무 시간표. `0 9 * * 1`은 "매주 월요일 9시 0분", `0 9 * * 1-5`는 "평일 9시".
- **일시정지(paused) 생성**: 스위치를 끈 채로 설치하기. 내용을 확인한 뒤 `resume`으로 켠다.

## 실습: 따라 하기

수업용으로 원문의 arXiv 논문 예시를 "내 분야 뉴스 주간 브리핑"으로 바꿨다. 수강생 서버에서 바로 해 볼 수 있는 가장 쉬운 길(기존 텔레그램 봇에서 만들기)과 원문 방식(별도 프로필)을 차례로 해 본다.

### 1단계: 직무를 한 문장으로 쓰기

아티클의 빈칸 채우기 공식이다.

> 매 [언제], [한 가지 일]을 해서 [하나의 결과물]을 내가 [승인/읽기/사용]하게 준다.

예시: "매주 월요일 오전 9시, 내 분야(예: 소상공인 마케팅) 이번 주 뉴스 5개를 찾아서, 각 줄에 출처 링크를 단 초안을 내가 읽게 준다."

10초 안에 결과가 좋은지 나쁜지 판단할 수 있으면 잘 쓴 문장이다.

### 2단계: 기존 봇으로 먼저 시험 근무 시키기

새 프로필을 만들기 전에, 지금 텔레그램 봇에서 한 번만 실행해 결과 품질을 본다.

```prompt
지금 한 번만 해 줘. 크론잡은 아직 만들지 마.
소상공인 마케팅 분야에서 이번 주 나온 국내 뉴스 5개를 찾아서
한 줄 요약 + 출처 링크로 정리해 줘.
확인 못 한 내용은 추측하지 말고 "미확인"이라고 적어.
```

결과가 마음에 들 때까지 문장을 다듬는다. 이 문장이 그대로 크론잡 지시문이 된다.

### 3단계: 일시정지 상태로 근무표 만들기 (기존 봇)

텔레그램에서 만든 크론잡은 결과가 같은 대화방으로 온다.

```prompt
2단계 지시문으로 크론잡을 하나 만들어 줘.
이름: 주간 뉴스 브리핑
시간: 매주 월요일 오전 9시 (한국 시간)
스킬: 웹 검색과 출처 표기에 필요한 것만
처음에는 일시정지 상태로 만들고, 만든 내용(시간, 지시문, 스킬)을 보여 줘.
내가 "켜"라고 하면 그때 켜 줘.
```

봇이 보여 준 내용을 읽고 "켜"라고 답한다. 바로 시험하려면 "지금 한 번 실행해 줘"라고 한다.

### 4단계: 별도 직원(프로필)으로 독립시키기

원문 방식이다. 라이트하우스 서버 까만 창에서 하거나, 봇에게 명령 실행을 맡긴다.

```bash
hermes profile create newsdesk --description "매주 내 분야 뉴스 5개를 출처 링크와 함께 요약하는 담당"
hermes profile list
```

직무기술서를 쓴다. 봇에게 맡겨도 된다.

```prompt
newsdesk 프로필의 SOUL.md를 아래 내용으로 바꿔 줘. 바꾸기 전에 전체 내용을 먼저 보여 주고 내 승인을 받아.

[뉴스데스크]
너는 뉴스데스크 직원이다.
[한 가지 일]
매주 내 분야 뉴스 5개를 한 줄 요약과 출처 링크로 정리한다.
[규칙]
- 초안만 만든다. 어디에도 게시하거나 보내지 않는다.
- 모든 줄에 공식 출처 링크를 단다.
- 확인 못 한 것은 "미확인"이라고 쓴다.
- 모든 답을 "뉴스데스크:"로 시작한다.
```

"뉴스데스크:"로 시작하는지 보면 직무기술서가 적용됐는지 바로 알 수 있다.

### 5단계: 직원의 근무표 만들기

원문 명령 구조를 따른 예시다. `-p newsdesk`는 "이 명령을 newsdesk 직원에게"라는 뜻이다.

```bash
hermes -p newsdesk cron create "0 9 * * 1" "이번 주 소상공인 마케팅 국내 뉴스 5개를 한 줄 요약과 출처 링크로 정리해. 초안만." --name "주간 뉴스 브리핑" --skill grounded-citations --paused --paused-reason "첫 실행 전 확인"
hermes -p newsdesk cron list
hermes -p newsdesk cron resume <작업ID>
```

### 6단계: 일주일 평가

```bash
hermes -p newsdesk cron runs
```

매주 한 줄씩 기록한다: 날짜, 실행됐는지, 결과, 내가 채택했는지. 쓸모없으면 해고한다.

```bash
hermes -p newsdesk cron remove <작업ID>
hermes profile delete newsdesk -y
```

삭제 전에 SOUL.md는 따로 복사해 둔다.

## 응용 아이디어

- **소상공인**: "매일 오전 8시, 우리 가게 네이버 리뷰 새 글을 모아 답글 초안 3개를 준다."
- **1인 크리에이터**: "매주 금요일, 내 분야 유튜브 인기 주제 5개를 쇼츠 아이디어 초안으로 준다."
- **강사**: "매주 일요일 밤, 다음 주 수업에 쓸 최신 사례 3개를 출처와 함께 준다."
- **직장인**: "평일 오전 7시, 오늘 일정과 중요한 메일을 5줄로 요약해 준다." (원문 아티클의 Morning Brief)
- **블로거**: "매주 월요일, 지난주 블로그 글 중 쓰레드로 다시 쓸 만한 글 1개를 골라 준다."

## 수강생 미션

### 기본 미션

1~3단계를 따라 기존 텔레그램 봇에 "주간 브리핑" 크론잡을 일시정지 상태로 만들고, 내용을 확인한 뒤 켠다. "지금 한 번 실행"으로 결과를 받아 본다.

제출물: 직무 한 문장, 크론잡 내용 캡처, 첫 실행 결과 캡처.

### 도전 미션

4~6단계를 따라 별도 직원(프로필)을 하나 뽑고, SOUL.md와 일시정지 근무표까지 만든다. 일주일 동안 근무 기록표를 쓴다.

제출물: `hermes profile list` 캡처, "뉴스데스크:"로 시작하는 답변 캡처, 일주일 근무 기록표(날짜, 실행 여부, 채택 여부).

## 체크리스트

- [ ] 직무를 "매 [언제], [한 가지 일], [하나의 결과물]" 한 문장으로 썼다
- [ ] 크론잡을 만들기 전에 한 번 수동 실행으로 품질을 확인했다
- [ ] 크론잡을 일시정지 상태로 만들고 내용을 읽은 뒤 켰다
- [ ] 지시문에 "초안만", "출처 링크", "미확인 표기"가 들어 있다
- [ ] (도전) 프로필 SOUL.md가 적용된 것을 응답 머리말로 확인했다
- [ ] 일주일 뒤 계속 둘지 해고할지 결정했다

## 주의할 점과 한계

- **게이트웨이가 꺼지면 근무도 멈춘다**: 크론잡은 게이트웨이가 실행한다. 봇이 조용하면 `hermes gateway restart`부터 한다.
- **새 프로필은 빈 책상**: 기본 생성은 메인 봇의 메모리와 성격을 가져가지 않는다. 아티클에 따르면 터미널에서 만든 프로필에는 OAuth 로그인도 복사되지 않아 `hermes -p <이름> auth add`로 따로 연결해야 할 수 있다. 우리 수업처럼 ChatGPT 구독(OAuth)을 쓰면 새 프로필에서 다시 인증이 필요할 수 있다.
- **새 직원의 결과를 텔레그램으로 받으려면**: 공식 문서상 텔레그램 봇 하나는 한 프로필에만 속한다. 별도 프로필의 결과를 텔레그램으로 받으려면 그 프로필에 메시징 설정이 따로 필요하다. 어렵다면 기본 미션처럼 기존 봇에서 크론잡을 만드는 것이 가장 쉽다. 터미널에서 만든 크론잡의 기본 전달 위치는 서버 안 파일(local)이다.
- **`--deliver` 플래그**: 원문 아티클은 `--deliver local` 같은 플래그를 쓴다. 공식 문서에서 전달 대상 값(origin, local, telegram)은 확인했지만, 이 플래그 이름 자체는 원문 작성자 제공이며 공식 문서에서 직접 확인하지 못했다.
- **"초안만"은 잠금장치가 아니다**: SOUL.md 규칙은 지침일 뿐이다. 위험한 명령을 막는 것은 승인(approvals) 설정이고, 크론 실행 중 위험 명령은 기본값(cron_mode: deny)으로 차단된다.
- **arXiv 예시는 영어권 논문용**: 원문 arxiv 스킬은 논문 검색 전용이다. 국내 뉴스용으로는 웹 검색과 출처 표기 스킬을 쓴다.
- **아티클의 전제 버전**: 원문 아티클은 Hermes Agent v0.22 이상을 전제로 한다. 수강생 서버 버전이 낮으면 명령이 다를 수 있다.

## 강사 노트

| 시간 | 내용 |
|---|---|
| 0~5분 | 원본 사례 소개, 직원 6요소 표 설명 |
| 5~10분 | 직무 한 문장 쓰기 실습 (각자 1문장 채팅창에 공유) |
| 10~20분 | 2~3단계 시연: 수동 1회 실행 → 일시정지 크론잡 → 켜기 |
| 20~27분 | 4~5단계 시연: 프로필, SOUL.md, "뉴스데스크:" 확인 |
| 27~30분 | 미션 안내, 해고(삭제) 방법과 주의점 |

시연 팁:

- 직무 문장 쓰기가 가장 중요하다. "블로그도 쓰고 뉴스도 보고"처럼 두 가지가 섞인 문장이 나오면 그 자리에서 둘로 쪼개 준다.
- 프로필 시연은 강사 서버에 미리 `newsdesk`를 만들어 두고, OAuth 재인증 장면은 녹화로 대체하면 시간이 절약된다.

예상 질문과 답:

- **Q. 직원을 많이 뽑으면 비용이 많이 드나요?** 실행 횟수만큼 모델을 쓴다. 주 1회 직원 3명은 매일 1회 직원 1명보다 적게 쓴다. 근무 빈도를 먼저 줄인다.
- **Q. 프로필을 꼭 나눠야 하나요?** 처음엔 아니다. 기존 봇에 크론잡 2~3개면 충분하다. 규칙이 섞이기 시작하면 그때 직원을 독립시킨다.
- **Q. 크론 표현식이 어려워요.** 봇에게 "매주 월요일 9시를 크론 표현식으로 바꿔 줘"라고 물으면 된다. 텔레그램 크론잡은 "매주 월요일 9시"처럼 말로 지정해도 된다.
