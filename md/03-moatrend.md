## 한 줄 요약

텔레그램에서 비서에게 "블로그 초안 잡아줘" 한 마디만 하면, 헤르메스 칸반(작업판)에 일이 등록되고 기획, 리서치, 콘텐츠, 검수 담당 봇이 차례로 나눠서 처리한다.

## 원본 사례

국내 사용자 Moa(@moatrend)는 2026년 10월 23일, 헤르메스 에이전트로 "텔레그램 안에 나만의 AI 팀"을 꾸렸다고 공유했다.

구조는 이렇다.

- 사용자는 평소 쓰는 텔레그램에서 비서 봇에게 일을 맡긴다.
- 맡긴 일은 칸반(작업판)에 카드로 등록된다.
- 기획, 리서치, 콘텐츠, 검수 담당이 카드를 나눠 맡아 진행한다.
- 사용자는 중간 질문에 답하고, 마지막 결과를 승인한다.

실제로 맡기는 요청의 예시도 함께 적었다.

> "이 사진으로 블로그 소재를 만들어줘", "맛집 후기 자료 모아서 블로그 초안 잡아줘" 이런 요청을 맡기는 방식. 나는 텔레그램에서 요청하고, 중간 질문에 답하고, 결과를 승인한다. (@moatrend)

솔직한 한계도 남겼다. 클로드 코드를 써서 하루 종일 설정과 씨름했는데도 아직 도구 문제로 멈출 때가 있다고 한다. 그래도 "작은 사무실이 완성"됐다고 마무리했다.

댓글에서 "그록봇 대신 헤르메스를 쓰는 장점이 뭐냐"는 질문에는 이렇게 답했다.

> 제 서버에 깔아서 원하는 모델을 연결하고, 평소 쓰는 텔레그램에서 일을 맡길 수 있다는 게 좋더라고요. 옵시디언에 모아둔 제 자료랑 연결해서 작업하기도 좋고요. 대신 처음 설정하고 오류 잡는 건 제가 해야 합니다. (@moatrend)

원문에는 프로필 이름, 명령어, 모델 같은 세부 설정이 공개되지 않았다. 이 교재의 실습은 같은 구조를 헤르메스 공식 기능(프로필 + 칸반)으로 다시 설계한 것이다.

## 왜 헤르메스반에 중요한가

우리는 지금까지 봇 한 명에게 모든 일을 시켰다. 밤 11시 크론잡이 블로그 글로 쓰레드와 카드뉴스를 만들고, 텔레그램으로 미리보기를 보내고, "통과"하면 버퍼로 예약했다.

이 사례는 그 다음 단계다.

- **같은 텔레그램, 같은 서버**: 새 앱을 배울 필요 없이 지금 쓰는 봇이 "팀장" 역할을 맡는다.
- **크론잡의 확장**: 지금은 크론잡 하나가 생성부터 미리보기까지 혼자 한다. 역할을 나누면 리서치, 글쓰기, 검수를 각각 잘하는 담당자가 맡는다.
- **승인 규칙 유지**: Moa도 "결과를 승인한다"고 했다. 우리가 5차시에 배운 "미리보기 후 통과" 습관이 팀 구조에서도 그대로 핵심이다.
- **검수 담당의 의미**: 카드뉴스에 틀린 정보가 들어가는 사고를 사람 대신 검수 담당이 먼저 걸러 준다.

## 구조 한눈에 보기

```flow
텔레그램 요청 | "맛집 후기 모아서 블로그 초안 잡아줘"
비서(팀장) 봇 | 요청을 칸반 카드로 등록
칸반 분해 | 프로필 설명을 읽고 담당자별 하위 작업으로 나눔
리서치 담당 | 자료 수집, 출처 정리
콘텐츠 담당 | 리서치 결과로 초안 작성
검수 담당 | 사실 확인, 맞춤법, 금지 표현 점검
내 승인 | 텔레그램으로 결과를 받고 통과 또는 수정
```

카드는 "부모 작업이 끝나야 자식 작업이 시작"되는 순서로 움직인다. 리서치가 끝나기 전에는 글쓰기가 시작되지 않는다. 앞 담당자가 남긴 요약은 다음 담당자에게 자동으로 넘어간다.

## 핵심 개념

- **프로필(Profile)**: 직원 한 명의 책상. 각자 설정, 메모리, 스킬, 크론잡을 따로 가진다.
- **프로필 설명(description)**: 직원 명찰. 칸반이 "이 일은 누구에게 줄까"를 정할 때 이 설명을 읽는다.
- **칸반(Kanban)**: 사무실 화이트보드. 할 일 카드가 대기, 준비, 진행 중, 막힘, 완료 칸으로 이동한다.
- **디스패처(Dispatcher)**: 화이트보드를 보고 1분마다 일을 나눠 주는 반장. 게이트웨이 안에서 돈다.
- **분해(Decompose)**: 큰 일 하나를 담당자별 작은 일로 쪼개는 것. 기본값은 자동.

## 실습: 따라 하기

라이트하우스 서버의 헤르메스와 텔레그램 봇이 정상 작동하는 상태에서 시작한다. 봇이 대답을 안 하면 먼저 `hermes model`과 `hermes gateway restart`로 점검한다.

### 1단계: 팀 구성 계획 세우기

먼저 봇에게 계획만 받는다. 바로 만들지 않는다.

```prompt
블로그 글 하나를 만드는 AI 팀을 칸반으로 꾸리고 싶어.
담당자는 리서치, 콘텐츠, 검수 3명이야.
헤르메스 프로필로 만들 계획을 보여 줘.
각 프로필 이름(영문 소문자), 한 줄 역할 설명(description), 실행할 명령어를 표로 정리해 줘.
아직 실행하지 말고 내 승인을 기다려.
```

봇이 보여 준 표에서 역할 설명이 구체적인지 확인한다. 설명이 곧 칸반의 배정 기준이다.

### 2단계: 프로필 3개 만들기

계획이 괜찮으면 승인한다. 서버에서 직접 한다면 아래 명령과 같다.

```bash
hermes profile create researcher --description "블로그 주제의 자료를 웹에서 모으고 출처 링크와 함께 요약한다"
hermes profile create writer --description "리서치 요약을 바탕으로 블로그 초안과 쓰레드 글을 쓴다"
hermes profile create reviewer --description "초안의 사실, 출처, 맞춤법, 과장 표현을 점검하고 수정 요청을 남긴다"
hermes profile list
```

```prompt
좋아, 계획대로 프로필 3개를 만들어 줘.
끝나면 hermes profile list 결과를 보여 줘.
```

새 프로필은 메인 봇의 메모리와 성격을 가져가지 않는 빈 책상이다. 모델 로그인이 필요하다고 나오면 봇에게 "researcher 프로필도 지금 쓰는 모델로 쓸 수 있게 설정 방법을 알려 줘"라고 묻는다.

### 3단계: 텔레그램 봇에 칸반 권한 주기

지금 쓰는 텔레그램 봇이 칸반 카드를 만들 수 있게 도구를 켠다.

```bash
hermes tools enable kanban --platform telegram
hermes gateway restart
```

```prompt
텔레그램에서 칸반 도구를 쓸 수 있게 켜 줘.
명령은 hermes tools enable kanban --platform telegram 이야.
켠 다음 게이트웨이를 재시작해야 하면 방법을 알려 줘.
```

설정을 바꾼 뒤에는 텔레그램에서 `/new`로 새 대화를 시작해야 적용된다.

### 4단계: 첫 작업 맡기기

```prompt
칸반에 작업 하나를 만들어 줘.
제목: 우리 동네 카페 3곳 비교 블로그 초안
순서: researcher가 자료와 출처 정리 → writer가 초안 작성 → reviewer가 검수
마지막 결과는 발행하지 말고 텔레그램으로 미리보기만 보내.
진행 중에 나에게 물어볼 게 있으면 텔레그램으로 질문해.
```

### 5단계: 진행 상황 확인과 승인

```prompt
방금 만든 칸반 작업들의 상태를 칸별로 보여 줘.
막힌 작업이 있으면 이유를 알려 줘.
```

결과가 오면 5차시 규칙대로 "통과", "취소", "수정: ..." 중 하나로 답한다. 이 단계까지는 어디에도 자동 발행하지 않는다.

## 응용 아이디어

- **소상공인(음식점, 카페)**: 리서치(이번 주 지역 행사) → 콘텐츠(인스타 문구 3안) → 검수(가격, 영업시간 확인).
- **1인 크리에이터**: 리서치(유튜브 댓글 질문 모으기) → 콘텐츠(쇼츠 대본) → 검수(저작권, 과장 표현 점검).
- **강사**: 리서치(최신 사례 수집) → 콘텐츠(강의 슬라이드 개요) → 검수(출처 링크가 살아 있는지 확인).
- **직장인**: 리서치(경쟁사 뉴스) → 콘텐츠(주간 보고 초안) → 검수(숫자와 날짜 대조).
- **부동산, 보험 설계사**: 리서치(정책 변경 기사) → 콘텐츠(고객 안내 문자) → 검수(규정상 금지 표현 확인).

## 수강생 미션

### 기본 미션

프로필 3개(리서치, 콘텐츠, 검수)를 만들고, 칸반으로 블로그 초안 1건을 끝까지 돌려 본다.

제출물: `hermes profile list` 결과 캡처 1장, 텔레그램으로 받은 최종 미리보기 캡처 1장.

### 도전 미션

3차시에 만든 밤 11시 크론잡의 앞부분을 칸반으로 바꾼다. 크론잡이 직접 글을 쓰는 대신 "칸반에 작업을 만들고, 검수까지 끝난 결과만 미리보기로 보내기"로 고친다. 5차시 규칙(통과해야 버퍼 예약, 아침 8시까지 답 없으면 발행 안 함)은 그대로 유지한다.

제출물: 바뀐 크론잡 설명(봇에게 "등록된 크론잡 보여 줘"로 받은 내용) 캡처, 일주일 동안의 통과/수정 기록.

## 체크리스트

- [ ] 프로필마다 구체적인 한 줄 역할 설명(description)을 넣었다
- [ ] `hermes profile list`에 3개 프로필이 보인다
- [ ] 텔레그램에서 칸반 도구를 켜고 새 대화(`/new`)를 시작했다
- [ ] 작업이 리서치 → 콘텐츠 → 검수 순서로 진행되는 것을 확인했다
- [ ] 막힌 작업이 생기면 이유를 봇에게 물어 해결했다
- [ ] 최종 결과는 미리보기로만 받고 직접 승인했다
- [ ] 비용이 걱정되면 담당자 수를 3명 이하로 유지했다

## 주의할 점과 한계

- **원문 설정은 비공개**: Moa는 프로필 이름, 명령어, 모델을 공개하지 않았다. 이 교재의 실습은 헤르메스 공식 문서의 칸반 기능으로 재구성한 것이다.
- **설정이 어렵다**: 원작성자도 하루 종일 씨름했고 "도구 문제로 멈출 때가 있다"고 했다. 처음엔 담당자 2~3명으로 작게 시작한다.
- **비용**: 담당자가 늘면 모델 호출도 늘어난다. 한 작업이 3명을 거치면 대략 3배 이상 쓴다고 생각하고, 구독 한도를 확인한다.
- **봇 토큰은 한 프로필에만**: 공식 문서에 따르면 텔레그램 봇 하나는 한 프로필에만 속한다. 담당자마다 별도 텔레그램 봇이 필요한 것은 아니며, 기존 봇이 팀장 역할을 하고 나머지는 칸반으로 일을 받는다.
- **대시보드 주소**: `hermes dashboard`는 서버 안에서 `127.0.0.1:9119`로 열린다. 라이트하우스 서버에서는 바로 브라우저로 볼 수 없으니, 수업에서는 텔레그램으로 상태를 묻는 방법을 쓴다.
- **자동 분해 비용**: 칸반의 대기(Triage) 칸에 넣은 작업은 기본 설정에서 자동으로 쪼개진다. 한 번에 많은 작업을 넣지 않는다.
- **검수 담당도 AI다**: 검수 담당이 통과시켜도 최종 확인은 사람이 한다.

## 강사 노트

| 시간 | 내용 |
|---|---|
| 0~5분 | 원본 사례 소개, "작은 사무실" 구조도 설명 |
| 5~10분 | 프로필과 역할 설명이 왜 중요한지 (명찰 비유) |
| 10~22분 | 1~4단계 시연: 계획 → 프로필 생성 → 칸반 켜기 → 첫 작업 |
| 22~27분 | 진행 상황 확인, 통과 답장 시연 |
| 27~30분 | 미션 안내, 비용과 한계 짚기 |

시연 팁:

- 수업 전에 강사 서버에 프로필 3개와 칸반을 미리 켜 두고, 완료된 작업 1건을 준비해 둔다. 실시간 진행은 디스패처가 1분 단위로 돌아 느릴 수 있다.
- 처음에는 작업을 자동 분해에 맡기기보다 4단계처럼 순서를 직접 적어 주면 결과가 안정적이다.

예상 질문과 답:

- **Q. 봇을 여러 개 만들면 텔레그램 봇도 여러 개 필요한가요?** 아니다. 기존 봇 하나가 칸반에 일을 등록하고, 나머지 담당자는 서버 안에서 일을 받는다.
- **Q. 그록봇이나 다른 서비스로도 되나요?** 비슷한 구조는 가능하다. Moa의 말처럼 헤르메스는 내 서버, 내가 고른 모델, 내 자료(옵시디언 등)와 연결하는 자유도가 장점이고, 대신 설정과 오류 해결은 직접 해야 한다.
- **Q. 작업이 멈췄어요.** 텔레그램에서 "막힌 칸반 작업과 이유 보여 줘"라고 묻는다. 같은 오류가 연속 2번 나면 자동으로 막힘(Blocked) 칸으로 간다.
