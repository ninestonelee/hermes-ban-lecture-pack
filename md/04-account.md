## 한 줄 요약

에이전트를 도입할 때 가장 먼저 할 일은 툴 고르기가 아니라, 에이전트만 쓰는 계정과 공간(놀이터)을 따로 만들어 "이 안에서만 일해"라고 경계를 정해 주는 것이다.

## 원본 사례

2026년 11월 13일, "AI Company Builder"를 소개하는 국내 사용자 배배(@EKBaeAI)가 X에 짧은 보안 조언을 올렸다. 핵심은 이 문장이다.

> "AI 에이전트 도입할 때 제일 먼저 할 일은 툴 고르기가 아니라 '에이전트 전용 계정' 만들기예요." (@EKBaeAI)

작성자는 많은 사람이 자기가 쓰던 PC와 메인 메일에 바로 에이전트를 붙이는데, 그건 "진짜 비추"라고 말한다. 올해 초 OpenClaw와 헤르메스가 나왔을 때 사람들이 로컬 PC에 설치할 수 있었는데도 굳이 맥미니를 새로 샀던 이유가 "데이터 없는 빈 PC에서 시작하라"는 원칙 때문이었다는 것이다. (이 원칙의 출처는 작성자가 밝히지 않았다.)

작성자가 제안한 방법은 네 가지다.

- 에이전트 전용 Gmail을 새로 만든다.
- 그 계정에 딸린 드라이브, 캘린더 안에서만 일하게 한다.
- 개인용 AI와 회사용 AI를 분리한다.
- 회사 안에서도 대표, 인사처럼 민감한 정보를 보는 AI와 영업팀 AI를 나눈다.

작성자 본인의 구조도 소개했다. 그록봇에게 보내는 일은 거의 다 그록 전용 이메일로 보내고, 그록봇은 메일이 오면 지침을 받아 일한다. 전체를 지휘하는 메인 오케스트레이터는 헤르메스다.

답글에서는 "개인용과 회사용을 나누면 둘 다 알아야 하는 일정은 어떻게 하나"라는 질문이 나왔다. 작성자는 "일정은 공용 캘린더"로 해결한다고 답했다. 그리고 코인 서비스를 처음 쓸 때 원래 지갑 대신 따로 만든 지갑을 연결하는 것처럼, 새 에이전트 서비스도 그런 마음으로 대한다고 덧붙였다.

## 왜 헤르메스반에 중요한가

우리 수업에서 만든 봇은 이미 많은 출입증을 들고 있다.

- 텔레그램 봇 토큰 (봇을 움직이는 열쇠)
- ChatGPT/Codex 구독 로그인 (모델을 쓰는 열쇠)
- 버퍼 API 키 (쓰레드, 인스타에 예약 게시하는 열쇠)

5차시에서 "API 키 = 출입증"이라고 배웠다. 이번 사례는 한 걸음 더 나간다. 출입증을 어디에 꽂을지, 즉 어떤 계정을 연결할지가 더 중요하다는 것이다. 봇이 내 메인 메일, 내 메인 드라이브에 연결되어 있으면 실수 한 번이 내 삶 전체로 번진다. 에이전트 전용 계정에 연결되어 있으면 사고가 나도 그 놀이터 안에서 끝난다.

다행히 우리 수업 구조는 이미 절반은 지키고 있다. 헤르메스는 내 노트북이 아니라 라이트하우스 클라우드 서버, 즉 "데이터 없는 빈 컴퓨터"에서 돌고 있다. 이제 남은 것은 계정을 정리하는 일이다.

## 구조 한눈에 보기

```flow
나 (메인 계정) | 메인 메일, 개인 드라이브, 금융. 봇은 접근 금지
공용 캘린더 | 나와 봇이 함께 봐야 하는 일정만 공유
에이전트 전용 Gmail | 봇이 메일 받고 보내는 유일한 주소
전용 드라이브 폴더 | 봇이 읽고 쓰는 파일은 여기만
헤르메스 서버 | 라이트하우스, 데이터 없는 빈 컴퓨터에서 시작
업무용 프로필 분리 | 개인용 봇과 업무용 봇은 키와 기억을 따로
```

위에서 아래로 갈수록 봇이 마음껏 움직여도 되는 공간이다. 맨 위 메인 계정에는 봇의 손이 닿지 않게 하고, 꼭 필요한 정보만 공용 캘린더나 전용 폴더로 내려보낸다.

## 핵심 개념

- **에이전트 전용 계정**: 봇 전용 업무용 휴대폰을 따로 만들어 주는 것. 회사 기밀이 담긴 내 휴대폰을 통째로 빌려주지 않는다.
- **놀이터(작업 범위)**: 아이가 놀이터 울타리 안에서만 놀게 하는 것. 봇이 접근할 수 있는 폴더, 캘린더, 메일함을 정해 준다.
- **최소 권한**: 택배 기사에게 집 열쇠가 아니라 현관 무인택배함 비밀번호만 알려 주는 것. 일에 필요한 만큼만 권한을 준다.
- **프로필**: 같은 서버 안에 방을 여러 개 만드는 것. 헤르메스 공식 문서에 따르면 프로필마다 설정(config.yaml), 키(.env), 기억, 스킬, 크론잡이 따로 있다.
- **허용 사용자 목록**: 아파트 출입 명단. 텔레그램 봇에게 명령할 수 있는 사람을 정해 두지 않으면 모르는 사람도 말을 걸 수 있다.

## 실습: 따라 하기

모든 단계는 "보기만 하고 바꾸지 않기"부터 시작한다. 바꾸는 것은 내가 확인한 다음이다.

### 1단계: 내 봇이 지금 들고 있는 출입증 목록 만들기

텔레그램에서 내 봇에게 보낸다.

```prompt
지금 너에게 연결된 계정, API 키, MCP 서버, 로그인 목록을 표로 정리해 줘.
각 항목마다 "무엇을 할 수 있는지(읽기/쓰기/삭제/게시)"와 "어느 계정에 연결됐는지(개인/업무/전용)"를 적어 줘.
키 값은 절대 보여 주지 말고 이름만 적어. 아무것도 바꾸지 마.
```

결과를 보고 "개인" 표시가 붙은 항목에 동그라미를 친다. 그것이 정리 대상이다.

### 2단계: 에이전트 전용 Gmail 만들기 (내가 직접)

이 단계는 봇에게 시키지 않고 사람이 직접 한다.

1. 새 구글 계정을 만든다. 예: `내이름.bot@gmail.com`
2. 비밀번호는 비밀번호 관리자에 저장하고, 2단계 인증을 켠다.
3. 메인 계정에서 봇이 알아야 할 캘린더 하나만 새로 만들어 전용 계정에 "공유"한다. (작성자가 말한 "공용 캘린더")
4. 메인 드라이브에 `봇작업` 폴더를 하나 만들어 그 폴더만 전용 계정과 공유한다.

### 3단계: 텔레그램 허용 사용자 확인

공식 문서에 따르면 허용 목록이 없으면 기본은 "모두 거부"다. 그래도 명시해 두는 것이 안전하다. 봇에게 확인만 시킨다.

```prompt
서버의 ~/.hermes/.env 에 TELEGRAM_ALLOWED_USERS 또는 GATEWAY_ALLOWED_USERS 설정이 있는지,
그리고 GATEWAY_ALLOW_ALL_USERS 가 켜져 있는지 확인해서 알려 줘.
값(숫자 아이디)은 가리고 "있음/없음"만 알려 줘. 아무것도 바꾸지 마.
```

`GATEWAY_ALLOW_ALL_USERS=true`가 있으면 강사에게 알리고 함께 고친다. 공식 문서는 이 설정을 "아끼는 기계에서는 절대 켜지 말라"고 안내한다. 참고로 헤르메스는 .env 파일을 파일 쓰기 도구로 고치지 못하게 막아 두었으므로, 수정은 서버 까만 창에서 사람이 직접 한다.

### 4단계: 승인 설정 확인

```prompt
~/.hermes/config.yaml 의 approvals 설정(mode, timeout, cron_mode, deny)을 그대로 보여 주고,
각각이 무슨 뜻인지 초등학생도 알게 한 줄씩 설명해 줘. 바꾸지는 마.
```

공식 기본값은 `mode: smart`(위험해 보이는 명령만 판단해서 물어봄), `cron_mode: deny`(크론잡이 위험 명령을 만나면 자동 차단), `timeout: 300`(5분 안에 답이 없으면 거부)이다. 우리 밤 11시 크론잡이 혼자서 위험한 일을 못 하는 이유가 바로 `cron_mode: deny`다.

### 5단계 (선택): 업무용 프로필 따로 만들기

개인 비서 봇과 업무용 봇을 나누고 싶은 분만 한다. 서버 까만 창에서 실행한다.

```bash
hermes profile create work --no-credentials
work setup
```

공식 문서 기준으로 `hermes profile create`는 기본적으로 지금 프로필의 API 키와 모델을 가져온다. `--no-credentials`를 붙이면 키, 로그인, 모델을 하나도 복사하지 않은 빈 방이 생긴다. 업무용 키는 그 방에만 새로 넣는다. 프로필마다 텔레그램 봇 토큰도 따로 써야 한다(새 봇은 BotFather에서 하나 더 만든다).

## 응용 아이디어

- **소상공인**: 가게 예약 문의는 `가게이름.bot@gmail.com`으로만 받게 하고, 봇은 그 메일함에서 예약 초안만 만든다. 매출, 통장 관련 메일은 메인 계정에 그대로 둔다.
- **1인 크리에이터**: 버퍼에는 연습용 채널부터 연결해 2주간 돌려 본 뒤 본 채널을 연결한다. 작성자가 말한 "가짜 지갑부터 연결" 전략이다.
- **강사**: 수강생 명단과 연락처가 있는 시트는 봇에게 주지 않고, 이름을 지운 출석 통계 시트만 `봇작업` 폴더에 둔다.
- **직장인**: 회사 메일에는 절대 연결하지 않는다. 개인 학습, 블로그용 봇과 회사 일은 완전히 분리하고, 회사 도입은 회사 보안 담당과 상의한다.
- **팀 단위**: 작성자 조언처럼 대표/인사용 봇과 영업팀 봇을 다른 프로필로 나누고, 공유가 필요한 일정은 공용 캘린더로만 넘긴다.

## 수강생 미션

### 기본 미션

1단계 프롬프트로 "내 봇 출입증 표"를 받아, 개인 계정에 연결된 항목을 표시해 제출한다. 제출물: 표 캡처 1장 (키 값이 보이지 않는지 확인 후).

### 도전 미션

에이전트 전용 Gmail을 만들고, 공용 캘린더 1개와 `봇작업` 폴더 1개만 공유한 뒤, 봇에게 "공용 캘린더의 이번 주 일정 3개를 요약해 줘"를 시켜 성공 화면을 제출한다. 제출물: 공유 설정 화면 + 봇 답변 캡처.

## 체크리스트

- [ ] 내 봇이 들고 있는 출입증(키, 로그인, MCP) 목록을 알고 있다
- [ ] 메인 메일, 메인 드라이브에 봇이 직접 연결되어 있지 않다
- [ ] 에이전트 전용 계정이 있고 2단계 인증이 켜져 있다
- [ ] 봇과 공유하는 캘린더, 폴더는 꼭 필요한 것만이다
- [ ] 텔레그램 허용 사용자 설정을 확인했고 ALLOW_ALL은 꺼져 있다
- [ ] approvals 설정의 뜻을 설명할 수 있다
- [ ] 키를 채팅에 보냈다면 연결 확인 후 그 메시지를 지웠다

## 주의할 점과 한계

- 전용 계정을 만들어도 내가 메인 계정 자료를 봇에게 복사해 붙여 넣으면 소용이 없다. 경계는 계정보다 습관이다.
- 공식 문서는 헤르메스의 안전장치(승인, 쓰기 차단, 비밀값 가리기)가 "정직하지만 실수하는 에이전트"를 막는 가드레일이지, 악의적인 프로그램을 가두는 감옥은 아니라고 설명한다. 완전 격리가 필요하면 도커 같은 격리된 실행 환경이 따로 필요하다.
- `/yolo` 명령이나 승인 화면의 "always(항상 허용)"는 안전장치를 끄거나 영구 허용 목록에 넣는다. 수업 중에는 쓰지 않는다.
- 프로필 분리는 서버 하나 안에서의 분리다. 서버 자체가 털리면 모든 프로필이 위험하다.
- "올해 초 다들 맥미니를 샀다", "빈 PC에서 시작하라는 지침"은 작성자의 경험담이며 공식 문서 출처는 확인하지 못했다. 피클 보안이 "블랙박스"라는 평가도 작성자 의견이다.
- 구글 계정을 여러 개 만드는 것은 구글 정책을 따른다. 계정 생성, 전화번호 인증 조건은 바뀔 수 있다.

## 강사 노트

| 시간 | 내용 |
| --- | --- |
| 3분 | 원문 인용 한 줄 + "여러분 봇은 지금 어떤 출입증을 들고 있나요?" 질문 |
| 5분 | 구조도 설명: 메인 계정, 공용 캘린더, 전용 계정, 서버 |
| 7분 | 1단계, 4단계 실습 (보기만 하는 프롬프트) |
| 3분 | 5단계 프로필 분리 시연 (강사 화면) |
| 2분 | 미션 안내 |

시연 팁

- 강사 봇으로 1단계 프롬프트를 먼저 보여 주되, 화면 공유 전에 결과에 키 값이 섞여 나오지 않는지 한 번 확인한다. 헤르메스는 기본적으로 키처럼 보이는 값을 가리지만(redact_secrets) 100%는 아니다.
- 5차시 "API 키 = 출입증" 슬라이드를 다시 띄우고 "이번엔 출입증을 어느 건물에 꽂을지"로 연결한다.

예상 질문과 답

- Q. 이미 메인 Gmail을 연결해 버렸어요. 지금 끊어야 하나요?
  A. 급하게 끊기보다 먼저 1단계 표로 무엇을 하는지 확인하고, 전용 계정을 만든 뒤 하나씩 옮긴다. 구글 계정 보안 설정의 "서드파티 앱 연결" 화면에서 연결 해제할 수 있다.
- Q. 프로필을 나누면 봇이 두 개라 텔레그램 대화방도 두 개인가요?
  A. 맞다. 공식 문서 기준으로 프로필마다 자기 게이트웨이와 봇 토큰이 있어서, 텔레그램 봇도 따로 만든다.
- Q. 비밀번호 관리자는 꼭 써야 하나요?
  A. 계정이 늘어나면 기억에 의존하는 순간 같은 비밀번호를 재사용하게 된다. 무료 관리자라도 쓰는 것을 권한다. 헤르메스도 공식적으로 Bitwarden, 1Password에서 키를 가져오는 기능을 지원한다.
