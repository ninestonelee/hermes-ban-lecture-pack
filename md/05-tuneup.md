## 한 줄 요약

봇에게 "점검만 하고, 내가 OK하기 전에는 아무것도 바꾸지 마"라고 시킨 뒤, 기억, 공간, 속도, 보안, 자동 실행 다섯 가지를 표로 보고받는 주간 건강검진 프롬프트입니다.

## 원본 사례

2026년 11월 24일, 헤르메스 팁을 꾸준히 올리는 @BkashJosi(Hermes Super-Intel)가 "헤르메스 5분 튠업"이라는 글을 올렸습니다. 하루 만에 조회수가 1만 3천을 넘었습니다.

글의 핵심은 헤르메스에 그대로 붙여 넣는 프롬프트 하나입니다. 첫 문장이 가장 중요합니다.

> "내 헤르메스를 점검해 줘. 점검만 해. 내가 좋다고 하기 전까지 아무것도 바꾸지 마." (@BkashJosi, 번역)

그 다음 다섯 영역을 차례로 살피게 합니다.

| 영역 | 원문이 시킨 명령 | 봇에게 던지는 질문 |
|---|---|---|
| 기억(Memory) | hermes memory status, hermes curator status | 나에 대해 틀리거나 오래된 기억은? |
| 공간(Space) | hermes checkpoints status, hermes worktree audit, hermes sessions list | 공간을 차지하는 것과 지워도 안전한 것은? |
| 속도(Speed) | hermes prompt-size | 안 쓰는데 매 메시지를 무겁게 만드는 것은? |
| 보안(Security) | hermes security audit, hermes config get approvals | 위험하거나 낡은 설정은? |
| 자동 실행(Autopilot) | hermes cron list, hermes fallback list | 실패한 작업은? 예비 모델은 있나? |

마지막에는 "영역, 발견한 것, 해결책 하나, 정확한 명령어" 네 칸짜리 표로 정리하고, 어떤 해결책을 적용할지 물어보게 합니다. 작성자는 "읽기만 한다. 네가 좋다고 하기 전에는 아무것도 바뀌지 않는다"며 매주 일요일에 실행하라고 권했습니다.

댓글에는 "잘 맞춰 놨다고 생각했는데, 이 프롬프트로 고칠 것을 여러 개 찾았다"는 사용자 후기도 달렸습니다.

공식 문서로 명령어를 하나씩 확인해 보니 9개는 실제로 있는 명령이었고, `hermes worktree audit` 하나는 문서에 없었습니다(비슷한 기능은 `hermes worktree list`). 그래서 우리 교재 버전에서는 이 명령을 빼고, 우리 환경에 더 맞는 읽기 전용 명령으로 바꿨습니다.

## 왜 헤르메스반에 중요한가

- **5차시 승인 규칙의 연장입니다.** 크론잡에 "통과라고 하기 전엔 발행하지 않는다"를 넣었듯, 서버 점검에도 "OK하기 전엔 바꾸지 않는다"를 넣습니다. 같은 습관입니다.
- **봇이 조용해지는 원인을 미리 찾습니다.** 5차시 오프닝에서 "0번, 봇이 대답을 안 한다"를 다뤘습니다. 예비 모델(fallback)이 없거나 크론잡이 실패하는 것을 미리 보면 그런 날이 줄어듭니다.
- **밤 11시 크론잡을 지킵니다.** 매일 도는 크론잡이 실패하고 있어도 텔레그램에서는 잘 안 보입니다. 튠업이 실패 기록을 찾아 줍니다.
- **라이트하우스 서버는 작습니다.** 세션과 기록이 쌓이면 디스크가 찹니다. 공간 점검이 필요합니다.
- **까만 창을 몰라도 됩니다.** 명령어는 봇이 서버에서 직접 실행하고, 우리는 텔레그램에서 결과 표만 봅니다.

## 구조 한눈에 보기

```flow
일요일 아침 | 텔레그램으로 튠업 프롬프트 전송
읽기 전용 점검 | 봇이 서버에서 점검 명령만 실행
결과 표 | 영역, 발견, 해결책, 명령어 4칸 표
내 선택 | "2번만 적용해" 또는 "이번 주는 패스"
적용과 확인 | 고른 것만 적용 후 다시 점검
```

핵심은 3단계와 4단계 사이입니다. 봇이 표를 보여 주고 멈추는 지점이 있어야 합니다. 이 멈춤이 없으면 튠업이 아니라 "봇 마음대로 정리하기"가 됩니다.

## 핵심 개념

- **읽기 전용(Check only)**: 건강검진처럼 보기만 하고 수술은 안 하는 것. 상태를 보는 명령만 씁니다.
- **크론잡(cron)**: 정해진 시간에 자동으로 일하는 알람. 우리 밤 11시 작업이 이것입니다.
- **예비 모델(fallback)**: 주 모델이 한도에 걸리거나 먹통일 때 대신 나서는 교체 선수.
- **프롬프트 크기(prompt-size)**: 매 메시지마다 봇이 짊어지고 가는 기본 가방 무게. 안 쓰는 스킬이 많으면 가방이 무거워져 느리고 비싸집니다.
- **승인 모드(approvals)**: 위험한 명령 앞에서 봇이 "해도 될까요?" 묻는 방식. smart, manual, off 세 가지가 있고 off는 위험합니다.

## 실습: 따라 하기

### 1단계: 봇이 살아 있는지 확인

```prompt
지금 서버에서 hermes status 를 실행해서 결과를 세 줄로 요약해 줘. 아무것도 바꾸지 마.
```

대답이 없으면 5차시에 배운 순서대로 복구합니다.

```bash
hermes model
hermes gateway restart
```

### 2단계: 한국어 튠업 프롬프트 보내기

아래 프롬프트를 그대로 복사해 텔레그램 봇에게 보냅니다. 원문을 우리 환경(라이트하우스 서버, 텔레그램, 밤 11시 크론잡, 버퍼)에 맞게 바꾼 버전입니다.

```prompt
내 헤르메스 튠업을 해 줘.
규칙: 점검만 해. 내가 "적용"이라고 답하기 전까지 아무것도 바꾸거나 지우지 마.
명령은 이 서버에서 직접 실행하고, 결과는 쉬운 한국어로 설명해 줘.

1) 기억: hermes memory status 와 hermes curator status 를 실행해.
   그리고 네가 나에 대해 기억하는 것 중 틀렸거나 오래된 것이 있으면 알려 줘.
2) 공간: df -h 로 서버 디스크 남은 용량을 보고, hermes checkpoints status 와 hermes sessions stats 를 실행해.
   무엇이 공간을 차지하는지, 지워도 안전한 것은 무엇인지 알려 줘.
3) 속도: hermes prompt-size --platform telegram 을 실행해.
   내가 안 쓰는데 매 메시지를 무겁게 만드는 스킬이나 도구가 있는지 알려 줘.
4) 보안: hermes security audit 와 hermes config get approvals 를 실행해.
   위험하거나 오래된 것이 있는지 알려 줘. 키나 비밀번호 값은 절대 화면에 보여 주지 마.
5) 자동 실행: hermes cron list, hermes cron doctor, hermes fallback list 를 실행해.
   밤 11시 크론잡이 최근에 실패한 적이 있는지, 예비 모델이 있는지 알려 줘.

마지막에 표 하나로 정리해 줘: 번호, 영역, 발견한 것, 해결책 하나, 정확한 명령어.
문제가 없는 영역은 "이상 없음"이라고 적어 줘.
그리고 어떤 번호를 적용할지 나에게 물어봐.
```

### 3단계: 결과 표 읽기

봇이 표를 보내면 세 가지만 확인합니다.

- 자동 실행 칸에 "실패"가 있는가? 있다면 가장 먼저 봅니다.
- 예비 모델이 "없음"인가? 없으면 주 모델이 한도에 걸린 날 크론잡이 멈춥니다.
- 보안 칸에 approvals mode 가 off 로 나오는가? off 라면 반드시 고칩니다.

### 4단계: 하나만 골라 적용하기

처음에는 한 번에 하나씩만 적용합니다.

```prompt
표의 3번만 적용해 줘. 적용하기 전에 실행할 명령을 먼저 보여 주고 내 "통과"를 받아.
적용한 뒤에는 같은 점검을 다시 실행해서 바뀐 결과를 보여 줘.
```

삭제가 들어간 해결책이면 한 줄을 더 붙입니다.

```prompt
지우기 전에 지울 대상 목록과 크기를 먼저 보여 줘. 되돌릴 수 없는 삭제면 미리 말해 줘.
```

### 5단계: 매주 일요일 크론잡으로 만들기 (선택)

```prompt
매주 일요일 오전 10시에 방금 쓴 튠업 점검을 실행하는 크론잡을 만들어 줘.
점검만 하고 절대 적용하지 마. 결과 표만 텔레그램으로 보내 줘.
만들기 전에 크론잡 내용을 먼저 보여 주고 내 승인을 받아.
```

크론잡이 등록되면 "등록된 크론잡 보여 줘"로 확인합니다.

## 응용 아이디어

- **소상공인**: 예약, 주문 알림 크론잡이 있다면 "지난주 실패한 알림이 있었는지"를 자동 실행 칸에 추가.
- **1인 크리에이터**: "버퍼 예약 큐에 남은 게시물 수"를 묻는 줄을 추가해 다음 주 예약이 비어 있는지 확인.
- **강사**: 수강생에게 같은 프롬프트를 배포하고, 결과 표 캡처를 받아 개별 지원 대상을 빠르게 분류.
- **직장인**: 회사 메일, 캘린더를 연결했다면 보안 칸에 "연결된 계정과 권한 목록 보여 줘"를 추가.
- **봇이 여러 개인 분**: 봇마다 따로 튠업을 돌리고 표를 나란히 비교.

## 수강생 미션

### 기본 미션

- 2단계 한국어 튠업 프롬프트를 내 봇에게 1회 실행합니다.
- 제출물: 결과 표 캡처 1장 + "가장 먼저 고칠 것 하나와 이유" 한 줄.

### 도전 미션

- 표에서 하나를 골라 4단계 방식(명령 미리보기, 통과, 재점검)으로 적용합니다.
- 5단계 일요일 튠업 크론잡을 등록합니다.
- 제출물: 적용 전후 표 캡처 + "등록된 크론잡 보여 줘" 결과 캡처.

## 체크리스트

- [ ] 프롬프트 첫 줄에 "점검만, 적용이라고 하기 전엔 바꾸지 마"가 들어 있다
- [ ] 봇이 표를 보여 준 뒤 멈추고 나에게 물었다
- [ ] 밤 11시 크론잡의 최근 실패 여부를 확인했다
- [ ] 예비 모델(fallback) 유무를 확인했다
- [ ] approvals mode 가 off 가 아닌 것을 확인했다
- [ ] 결과 화면에 API 키나 비밀번호가 보이지 않았다
- [ ] 적용은 한 번에 하나씩, 미리보기 후 통과로 진행했다

## 주의할 점과 한계

- **"점검만"은 약속일 뿐 잠금이 아닙니다.** 봇이 실수로 고칠 수도 있습니다. 승인 모드를 off 로 두지 말고, 이상한 명령이 보이면 바로 "멈춰"라고 보냅니다.
- **원문 명령 중 하나는 공식 문서에 없습니다.** `hermes worktree audit` 은 확인되지 않아 뺐습니다(워크트리는 개발자용 기능이라 우리 수업에는 필요 없습니다).
- **hermes memory status 는 외부 메모리 설정을 보여 줍니다.** 봇이 나에 대해 무엇을 기억하는지는 명령보다 "나에 대해 뭘 기억하고 있어?"라고 직접 묻는 쪽이 정확합니다.
- **hermes security audit 은 외부 취약점 데이터베이스(OSV.dev)에 조회합니다.** 서버 인터넷이 막혀 있으면 실패할 수 있습니다.
- **비용**: 점검 자체는 대부분 오프라인 명령이지만, 결과를 읽고 설명하는 데 모델 사용량이 듭니다. 매일이 아니라 주 1회면 충분합니다.
- **버전 차이**: 명령어는 2026년 11월 공식 문서 기준입니다. 서버 헤르메스가 오래됐다면 없는 명령이 있을 수 있습니다. 봇이 "그런 명령이 없다"고 하면 그 줄은 건너뛰게 합니다.
- **"5분"은 작성자 주장**입니다. 스킬과 세션이 많으면 더 걸립니다.

## 강사 노트

| 시간 | 내용 |
|---|---|
| 0~3분 | 원본 사례 소개, "5차시 통과 규칙과 같은 습관" 연결 |
| 3~5분 | 1단계 봇 생존 확인 (안 되면 hermes model, gateway restart) |
| 5~12분 | 2단계 프롬프트 동시 실행, 강사 봇 결과 화면 공유 |
| 12~17분 | 3단계 표 읽기: 실패, 예비 모델, 승인 모드 세 칸만 짚기 |
| 17~20분 | 4단계 시연 1건 + 5단계 크론잡은 과제로 |

시연 팁:
- 강사 봇에서 미리 한 번 돌려 결과를 확인해 둡니다. 키 값이 화면에 나오는지 꼭 확인한 뒤 공유합니다.
- 일부러 예비 모델이 없는 상태를 보여 주면 "왜 필요한지"가 바로 전달됩니다.
- 결과 표가 길면 "표는 5줄 이내로"라고 덧붙이게 합니다.

예상 질문:
- **Q. 봇이 결과 대신 "명령을 찾을 수 없다"고 해요.** A. 헤르메스 버전 차이입니다. 그 줄은 건너뛰라고 하고, 나중에 업데이트를 검토합니다.
- **Q. 예비 모델은 어떻게 추가하나요?** A. 서버에서 `hermes fallback add` 로 고르는 방식입니다. 구독 상태에 따라 다르므로 개별 지원 시간에 같이 합니다.
- **Q. 지워도 안전하다고 해서 그냥 다 지우라고 해도 되나요?** A. 안 됩니다. 목록과 크기를 먼저 보고, 하나씩 승인합니다. 다음 교재(undo-effects)의 복구 장치도 함께 설치하면 더 안전합니다.
